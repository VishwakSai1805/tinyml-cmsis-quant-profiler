# Pareto benchmark: FP32 vs INT8 vs INT4

_Generated by `scripts/run_sweep.py` - do not edit by hand._

## Method

* **Task**: 4-class sensor anomaly detection on 64-sample windows (normal / spike / burst / level-shift), synthetic data, 1,600 train / 400 held-out test windows.
* **Models**: `Conv1D(k1, s2) -> ReLU -> Conv1D(3, s2) -> ReLU -> Dense -> ArgMax`, widths swept over `c1-c2` in {4-8, 8-16, 16-32, 32-64} and first kernel `k1` in {3, 5}.
* **Precisions**: `FP32` (reference), `INT8` (W8A8), `INT4` (W4A8, min-max per-channel), `INT4-MSE` (W4A8, MSE-optimal clipping). Activations are always INT8; INT32 accumulators.
* **Accuracy** is mean +- std over 3 training seeds (integer Python reference, proven bit-exact against the target).
* **Footprints for INT rows are measured**, for the seed-0 model on a QEMU Cortex-M3 (`lm3s6965evb`, `-Os`, `arm-none-eabi-gcc`): arena peak from the runtime's allocator, MACs counted by the runtime, Flash `.model_rodata` from the linked ELF section table, engine code from `size` on `tiny_nn.o`.
* **FP32 rows are analytic**: Flash = 4 B x parameters (weights + bias only, no FP32 kernel is shipped), arena = same double-ended plan with 4 B activations.
* **Pareto objectives (all 3 simultaneously)**: maximise accuracy, minimise model Flash, minimise arena peak. A row is on the frontier if no other row is at least as good on all three and strictly better on one.
* QEMU is functional, not cycle-accurate, so no latency numbers are reported.

## Caveats

* Synthetic data; absolute accuracies are not transferable to real sensors. Relative trends are the point.
* 400 test windows -> one window = 0.25 pp; differences below ~1 pp are within noise (see std column).
* INT rows' Flash includes per-channel bias / multiplier / shift metadata; FP32 Flash is weights+bias only.
* Sweep wall-clock: 38s.
